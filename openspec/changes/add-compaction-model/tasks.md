# Tasks

Routing for `/opsx-apply-loop`: selected reviewer `oracle`; orchestrator mode `orchestrator-led`; focus mode `normal`. The user allows only `oracle` as a subagent, so the orchestrator owns every implementation task, and the reviewer is advisory only. At the user's direction, the reviewer from wave 2 onward is the claude.ai web app driven through the Kimi browser extension (`kimi-webbridge` with `online-llm-interactive`), acting in the `oracle` role: the same advisory-only rules, one chat per wave, later rounds resumed in that same chat. The local `oracle` subagent is not used for wave 2 or later. Wave 1's gate was already running on the local `oracle` when this direction was given. No ADR is required: the change adds an extension on an existing Pi hook and loads an existing package from a fork, without changing a recorded decision.

## 1. Wave 1 — Compaction-model extension

- [x] 1.1 (Owner: orchestrator) Create `extensions/compaction-model/config.ts`: parse the config JSON into `{ model, thinkingLevel?, decisionModel }` plus a list of unrecognized keys, or the name of the invalid field. `model` and `decisionModel` are `provider/modelId` split on the first `/` (default `decisionModel` `typesafe/jev-latest`); `thinkingLevel` is a Pi thinking level or `auto`. Verify with `test/compaction-model/config.test.ts` covering a valid config, each invalid field, invalid JSON, a model id containing `/`, an unrecognized key, and the default decision model.
- [x] 1.2 (Owner: orchestrator) Create `extensions/compaction-model/thinking.ts`: feature-detect `findOfType`/`classify` on the model registry, build the bounded state (token estimate, message counts, previous summary, split turn, file-op counts, last 16,000 characters of the serialized conversation), ask one `choice` question over `low`/`medium`/`high`, and after `classify()` resolves return `cancelled` if the signal is aborted, the `choice` when `stopReason` is `stop` and the choice is one of the options, or the reason Jev was unavailable otherwise. Verify with `test/compaction-model/thinking.test.ts` using a fake registry that resolves (never rejects) with the `host/pi/packages/ai/src/types.ts` answer shape: chosen level, missing methods (stock host), classifier not found, `stopReason: "error"`, `stopReason: "aborted"` with an aborted signal, an out-of-range choice, and a state excerpt of at most 16,000 characters.
- [x] 1.3 (Owner: orchestrator) Create `extensions/compaction-model/index.ts` as a handler factory taking `compact` and the config reader, with a default export wiring the real ones. On `session_before_compact`: return nothing for `openai-codex` sessions or a missing config file; otherwise validate the config, resolve the model (reject unknown and `api === "pi-virtual"` models) and credentials, apply the context-window check with the output limit `min(0.8 × reserveTokens, model.maxTokens)`, pick the thinking level (explicit, session level via `pi.getThinkingLevel()`, or Jev; no Jev and "no reasoning" for a non-reasoning model), restore carried file lists from a latest `fromHook` compaction entry, call `compact()` with the model (plus auth `baseUrl`), apiKey, headers, `event.customInstructions`, `event.signal`, the level, env, and the fixed retry policy, then show one outcome notification and return `{ compaction }`. Return `{ cancel: true }` when the signal is aborted after Jev, on a thrown `compact()`, or after `compact()` resolves; return nothing with one warning on every other failure. Verify that `npm run typecheck` passes and that `test/compaction-model/handler.test.ts` covers, with a fake `ctx` and an injected `compact`: the Codex skip; missing-file silence; invalid-config, unknown-model, virtual-model, missing-auth, and too-large fallbacks (too-large using a 500,000-token reserve against a 1M and a 200K model); success argument pass-through including `baseUrl`, custom instructions, signal, and each level source; a rejecting `compact` → warning containing its message and no second call; abort during and after `compact` → `{ cancel: true }` with no success notification; two compactions reading different configs use different models; a `threshold` reason with no instructions; file lists restored from a `fromHook` entry and not from a Pi-written one, and kept when the request then fails; a `reasoning: false` model makes no Jev call and reports "no reasoning"; an abort after Jev returns `{ cancel: true }` and never calls `compact`; an unrecognized config key still summarizes, with a separate warning naming the key; an explicit `off` on a `claude-bridge` model is reported as "Claude Code default effort"; exactly one outcome notification per handled compaction, with config warnings counted separately; and no call to `setModel` or `setThinkingLevel`.
- [x] 1.4 (Owner: orchestrator) Add `test/compaction-model/*.test.ts` to the root `npm test` script, and document the extension in `README.md`: the overview table row; the config file with Haiku 5.5, Sonnet 5.5, and `claude-bridge/claude-haiku-5-5` examples and `auto`; fallback rules, including the context-window arithmetic under a large `reserveTokens`; the Codex skip; and the requirement to load the bridge from the submodule and this extension through `settings.extensions`. Verify that `npm run check` passes, `openspec validate add-compaction-model --type change --strict` passes, and the README example parses with the 1.1 parser.
- [x] 1.5 (Owner: oracle — wave 1 review gate, advisory only) Review the completed wave 1 as a whole, not task by task, against `specs/compaction-model/spec.md` and `design.md`, under `review-convergence`. The reviewer reports findings and one `PROPOSED_REVIEW_ACTION`; it does not edit, assign work, or complete tasks. The orchestrator reconciles every finding and records the one authoritative `REVIEW_ACTION` (`PASS`, `PATCH`, `REBUILD`, or `HUMAN_DECISION`). A `PATCH` or `REBUILD` returns work to this wave. The sequence allows at most four review rounds and one recorded rebuild, and a terminal action is checked against the latest candidate revision and the frozen boundary. Log: `docs/plans/reviews/add-compaction-model-implementation-review.md`, section `## Wave 1 Review Sequence`.
